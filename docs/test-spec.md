# 営業日報システム テスト仕様書（ドラフト v0.2）

> 前提：[要件定義書](./requirements.md)・[画面定義書](./screens.md)・[API仕様書](./api.md)・[仕様決定記録](./decisions.md) に基づく。

## 1. テスト方針

### 1.1 テストレベル

| レベル | 対象 | 実施方法 | 本書での扱い |
|---|---|---|---|
| 単体テスト | バリデーション、権限判定、編集可否判定などのロジック | 自動テスト（開発者） | 観点のみ記載（3章） |
| API テスト | 各 API の入出力・権限・エラー | 自動テスト（HTTP レベル） | ケースを記載（4〜7章） |
| 画面テスト | 画面表示・入力・遷移 | 手動 or E2E 自動テスト | ケースを記載（8章） |
| シナリオテスト | 業務の一連の流れ | E2E 自動テスト + 手動 | ケースを記載（9章） |
| 非機能テスト | 性能・セキュリティ・端末 | ツール + 手動 | ケースを記載（10章） |

### 1.2 合格基準

- 全テストケースが合格していること
- 優先度「高」のケースで不合格が 0 件であること（開発完了の判定の必須条件）
- 単体テストのカバレッジ：権限判定・バリデーションのモジュールは分岐網羅 100%

### 1.3 優先度

| 優先度 | 基準 |
|---|---|
| 高 | 権限・データ整合性に関わるもの、主要業務が止まるもの |
| 中 | 入力チェック、表示内容の正しさ |
| 低 | 表示の体裁、まれな操作 |

## 11. 決定事項

作成時の未決事項は、[仕様決定記録](./decisions.md) の #16〜#19 で決定した。要点は次のとおり。

- 無効化された営業の過去の日報は、上長が引き続き閲覧できる（SC-T-03 手順6、#16）
- 部下人数に無効な部下は含めない（T-STF-12、#17）
- ログインは同じメールアドレスで5回連続失敗すると15分ロックする（T-NF-08、#18）
- 性能テストは営業200人・日報25万件・訪問記録75万件を前提にする（T-NF-01、#19）
